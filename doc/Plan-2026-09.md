# Plan: numeric core and syntax, September 2026

Three Claude Code sessions, one plan. This document is the coordination
point: each session reads it once at start, works its own section, and
records milestones in its `## Status` block at the bottom of its repo's copy.
The detailed specs it draws on are `diluvium-numeric-spec.md` and
`diluvium-syntax-proposals.md`, committed beside it; this file states what
is decided, in what order, and how the sessions hand off without waiting on
each other.

Commit this file and both specs to `doc/` in diluvium and in diluvium-drt.
The lab session reads them from diluvium.

## 0. Read this first

### 0.1 Spend

Read this plan and the two specs once. Then read only the files your
milestone names. Do not survey the repository, do not spin up exploratory
agents to "understand the codebase", and do not re-derive decisions this
plan already made. Subagents are for exactly two things: running the full
cross-target gate in parallel at a milestone boundary, and one review pass
of a milestone's diff before it merges. Everything else is one agent,
sequential. Measure before you believe a number, but measure once and write
it down. Prefer the existing gates (`examples/run-all.sh`, `expected.txt`,
the diluvium test suite) over new harnesses. When a task is done, say so in
one line in `## Status` with the commit hash, and move on. Under-explaining
is fine; the code and the gate are the record.

### 0.2 Decide, record, proceed

When a question comes up that this plan does not answer, choose the option
most consistent with section 1's principles, write one line under
`## Decisions` in your `## Status` block, and continue. Do not stop to ask.

Stop and wait for the owner only for these:

- A change to `dv.h` beyond what section 3 declares.
- Anything that would make a valid Lua 5.5 program parse or behave
  differently (the freeness test in 3.6 is the check).
- Any change to the behavior of a shipped DRT connector, or any edit under
  the WireGuard, tunnel, relay, TURN, STUN or netcheck code. Those just
  started working in the field; they are not touched this round.
- Any change to how `drt-config` parses a field that exists today. New
  fields are added beside existing ones, never by reworking a shared path,
  and the loader corpus in 3.8 is the check. Every shipped install runs a
  config this loader wrote; a regression here is not caught by any other
  gate.
- A new dependency that adds more than 1 MB to any artifact, or any
  dependency with a non-permissive license.
- Anything that would change the dump/undump format or add an opcode.

### 0.3 Branches and merges

Each session works on one branch (`numeric-syntax` in diluvium, `numeric`
in diluvium-drt, `syntax-highlighting` in lab). Merge to `main` at a
milestone only when the full gate passes on every target CI runs. Never cut
a release or move a tag; leave CHANGELOG entries as `status: unreleased`.
The owner releases.

## 1. What we are building, and the principles that decide ties

Diluvium gains typed arrays, portable numeric kernels, an embedded libm
that makes float transcendentals bit-identical across targets, FFT and NTT,
and a set of syntax additions. DRT gains a `features` compatibility fact,
a raw-buffer lane in the hostcall reply, a parquet/CSV connector, and the
config surface that bounds numeric work per instance. The lab and homepage
gain highlighting for the new syntax and a size ledger for the web profile.

Principles, in the order they win ties:

1. **100% Lua compatibility.** Every new syntax form is a parse error in
   stock Lua 5.5. No new opcodes; desugars emit existing bytecode.
2. **Determinism is reported, not enforced**, except where a program opts
   in (`<deterministic>`). Bit-identical across native, wasm, browser and
   Windows is the reproducible tier's contract.
3. **Core patches minimal**, maintained as the patch series against
   upstream. Everything expressible through `lua.h`/`lauxlib.h` is on-top C.
4. **Feature-gated.** A build without `numeric` is byte-identical to today.
   `slim` stays exactly what it is.
5. **Nothing here needs a new build every four hours.** The shipping DRT
   release path is untouched; this work lands behind a flag and a pin.

Out of scope this round, do not build or explore: GPU backend, yieldable
kernels, the dataframe/stats/ML dlua packages (a later session, see 7),
braces, inline type annotations, Tier D syntax, decQuad (not a dependency
of anything here; arrays are `f64`/`i64`/`u8`).

## 3. Interfaces between sessions

These are fixed so no session waits on another to learn a shape.

### 3.1 `dv.h` additions (diluvium publishes in A0, DRT compiles against)

```c
/* Newline-separated feature names this build carries, e.g. "regex\nnumeric".
   Stable for the life of the process. */
const char *dv_features(void);

/* Monotonic build number, the N in 5.5.1_buildN. */
int dv_build(void);

/* Adopt a host-owned buffer into an array value on the instance's stack.
   dtype: 0=f64 1=i64 2=u8. Takes ownership of `bytes`, which must have
   been allocated with the instance's lua_Alloc. Without DV_NUMERIC this
   pushes a Lua string copy instead and returns 1; returns 0 on adoption. */
int dv_array_adopt(dv_instance *inst, int dtype, size_t len, void *bytes);

/* Backend vtable. Declared this round so the shape is fixed; only the
   portable implementation exists. Every entry carries its tier. */
typedef enum { DV_TIER_EXACT, DV_TIER_REPRODUCIBLE, DV_TIER_FAST } dv_tier;
typedef struct dv_numeric_backend {
  int abi;             /* 1 */
  const char *name;    /* "portable" */
  /* function pointers added as kernels land; each paired with a dv_tier */
} dv_numeric_backend;

/* Per-instance numeric bounds and status. */
void dv_numeric_set_max_elements(dv_instance *inst, uint64_t n); /* 0 = none */
void dv_numeric_set_max_tier(dv_instance *inst, dv_tier t);
int  dv_numeric_touched_fast(dv_instance *inst); /* sticky flag for the audit trail */
```

`dv_abi` moves to 2. Rule for `doc/Release.md`: a DRT reports the highest
ABI it speaks and admits any package requiring less or equal.

### 3.2 Hostcall reply blob lane (DRT publishes in B1, diluvium consumes)

The reply struct in `drt-hostcall` gains `blobs: Vec<Vec<u8>>`. A payload
field that carries a column is `{dtype, len, blob: <index>}`. On the C side
`dv_reply_blob(inst, index, &ptr, &len)` reads it, and the connector's Lua
wrapper calls into `array` to adopt. Bytes never pass through the serde
encoding. If the current encoding turns out to be one where this is awkward
(JSON with no side channel), the side channel is added to the reply struct
and the payload references it by index; do not base64 a column.

### 3.3 Output format for cross-target examples

Numeric examples never print floats with `%g`. They print IEEE bit
patterns: `("%016x"):format(string.unpack("<I8", string.pack("<d", x)))`,
or `array.bits(a)` which does the same per element. This is what makes one
`expected.txt` valid on glibc, musl, wasmtime, Chromium and mingw, whose
CRTs format decimals differently.

### 3.4 Budget charging

Kernels charge the instruction budget by element count, never by time:
one instruction per 64 elements processed, checked at block boundaries, so
`exceeded` fires inside a GEMM and the exceed point is identical on every
target (replay depends on this). Session A implements the charging against
the hook in `src/dv.c`; session B exposes `max_elements` and `max_tier` in
the instance config and attenuates them at spawn like budgets.

### 3.5 Build flags for every TU under `numeric` and the embedded libm

`-ffp-contract=off -fno-fast-math -fexcess-precision=standard -fno-builtin`
on every target, including the `cc`-driven builds in `diluvium-sys` and
`drt-web`, and the mingw cross-build. GCC on aarch64 contracts by default;
this is the single most likely cause of a cross-target mismatch. A
"contraction canary" test computes an `a*b+c` whose fused and unfused
results differ and asserts the unfused bits. Never enable wasm relaxed-simd.
Embedded libm symbols are prefixed (`dv_exp`, `dv_sin`) so the compiler
cannot substitute or constant-fold the platform versions.

### 3.6 Freeness check

CI builds pristine upstream `luac` from the tree the patch series applies
to, feeds it `test/syntax/freeness/*.lua` (one file per new form), and
fails if any file parses. The reverse corpus (the Lua test suite plus the
examples) must produce identical output before and after.

### 3.7 Pin protocol

Session A records each milestone's commit hash in its `## Status`. Session
B moves the `diluvium` pin in `Cargo.lock` to that hash at the start of its
next milestone, runs the full gate, and records the result. Session B never
waits on A: every B milestone lists what it does if the pin it wants is not
there yet. Session C reads A's `## Status` for the syntax that has actually
landed and highlights only that.

### 3.8 Config-loader regression corpus

`drt-config` is shared by everything, and B2 and B3 both add fields to it.
Before either, session B captures every config shape that is deployed or
shipped into `crates/drt-config/tests/corpus/`, verbatim, not retyped:
the `wg.host.lua` that `wg.sh` writes on a customer machine (it contains
`connectors = { time = {} }`, an empty map through the `as_array` path
that rc6 fixed for five fields), `examples/deployment.json`, every
`.host.lua` under `examples/`, and the rendezvous config with `peers = {}`.
The test loads each, asserts it parses to the same structure it parses to
today (snapshot on first run), and runs in the examples gate. Any loader
change that fails a corpus file is wrong regardless of what it enables.

## 9. Anticipated blockers, pre-answered

- **`setjmp`/`longjmp` on wasm.** Already lowered in the existing wasm
  builds; kernels raising `lua_error` are fine. Do not redesign error
  handling.
- **Two build systems compile the same C.** diluvium's Makefile and
  `diluvium-sys`'s `build.rs`. Flags in 3.5 must reach both; the canary
  test is how you find out they did not.
- **`-fno-builtin` and the libm prefix.** Without both, the compiler will
  replace `exp(x)` with the platform call or fold constants, and the
  cross-target diff will fail on exactly one target for no visible reason.
- **`%g` on Windows.** Never print decimals in examples; 3.3.
- **wasm SIMD.** `-msimd128` is fine; relaxed-simd is not, ever.
- **The instruction hook.** It clears itself in the pcall-escape case
  (FM-4, upstream, known). Kernels charge the budget through the same hook;
  do not try to fix FM-4 here.
- **Lua's raw metamethod lookup.** Inherited `__tostring`/`__add` are not
  found through `__index`; the class desugar copies them. Already in the
  spec; do not rediscover it.
- **`__eq` on mixed operands.** Silently false in Lua; `array.eq` exists
  for this reason, same as decQuad's note.
- **Empty table ambiguity in DRT's config loader.** `{}` is both empty list
  and empty map; rc6 fixed five fields and every shipped `wg.host.lua`
  carries `connectors = { time = {} }`. The `numeric` block and the
  `columns` list in the `data` connector use the same `as_array`-tolerant
  path, added beside it, and the corpus in 3.8 is what proves the existing
  fields still load. This is the one item in the plan that can break
  installs already in the field.
- **`exec` still stalls the loop.** Not this round's problem and not to be
  fixed in passing.
- **Parquet string columns.** Dictionary-encoded per the spec: `i64` codes
  plus a Lua table of uniques. Do not return a table of strings for a
  million-row column.
- **Expected.txt drift from libm.** Some existing examples may change
  output in the last digits on some target after A3. Update the file, note
  the target and the function in the commit message, move on.
- **Windows `full` does not build.** `data` is `full` only; do not try to
  build `full` for Windows to test it.

  guest**: `dv_array_adopt` puts a value on the instance's Lua stack, and
  every guest-visible path — `queue.wait`, `queue.pop`, a hostcall reply —

  configurations: adopt into a parked instance and resume, and the guest is
  still parked on the same wait; push an ordinary message and the guest
  gets that, never the column. The bytes are charged either way, so a
  caller pays a column's memory to hand over nothing. Reported to A. The
  shape that would fit this lane is an adopted value delivered *as* a queue
  message; until something like it exists, the msgpack `bin` is the lane's
  only delivery and is the documented no-`numeric` behaviour rather than a
  degradation.
