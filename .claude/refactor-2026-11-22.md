# Refactor analysis, 2026-11-22

The owner asked for this ("DRT has turned into a monolith; I want it
cleaned up and simplified"). Read-only analysis of main at 32aa665.
Four read-only agents, one each on drt core, drt network modules, the
foundation crates, and connectors/web/tests. The bugs marked "checked"
were confirmed against the code. The rest come from the agents' reading
and still need a failing test before anyone fixes them.

## 1. De-monolith the `drt` crate

**D1. Registration tables instead of cfg sprawl.** (S-M, low risk)
- Connector families are listed by hand in 6 places: the
  `wire_connectors_with` arms, `carries_builtin`, `BUILTIN_FAMILIES`,
  buildinfo's list, `enabled_features`, and tests/supplied.rs. Replace
  them with one `connectors!` table, with hooks for ldap (prompt), exec
  (notice) and net (yields).
- Each of `drt start`'s 8 blocks appears twice, as a start arm
  (start.rs:629-757) and in the loop (781-838). Seven already share
  `start/collect/report`. Replace them with a `trait Block` and a
  `blocks(config)` that refuses a block the build lacks (this fixes B2).
- The REPL colon commands are an if-chain beside a separate help list
  (repl.rs:741-828). Replace it with one `(name, help, handler)` table.
- These tables are the dispatch maps human-surfaces.md asks for. They
  remove about 230 lines and about 36 `cfg` arms.

**D2. Pull wiring out of cli.rs into `wiring.rs`.** (S, low)
- `cli.rs:855-1366` holds `wire_connectors*`, plugins, `assemble*` and
  `dispatcher_for`.
- The "wire, then validate, then validate_grants, then build a
  Dispatcher" sequence exists 3 times: `cli::dispatcher_for`,
  `boot::wire`, and drt-web swarm.rs:191, which skips validate.
- boot imports up into cli. Moving the wiring removes that.

**D3. One verb dispatch.** (M, low)
- `cli::main` is 445 lines, dispatched in two phases, with
  `unreachable!` arms.
- The `wg check` (130 lines), tunnel (85) and netcheck (70) bodies are
  written inline in `main`.
- There are 45 `ExitCode::FAILURE` + `eprintln!` pairs.
- Change: each verb becomes `fn(&Cli) -> Result<u8, VerbError>` in its
  own module, with one error formatter. `main` ends at about 50 lines.
- Also move buildinfo to `buildinfo.rs`. Have `build.rs` emit the
  enabled features and derive the verbs from clap, replacing about 120
  hand-synced lines.

**D4. Split start.rs (1,402 lines).** (M, moves only)
- `DeployHost`, `DeployDriver` and `ArgsDelivery` go to
  `deployment.rs` (repl and drt-web already use them).
- The listener queue bridge (1021-1177) goes to listen.rs.
- `RelayBridge` (1236-1402) goes to relay.rs.
- start.rs keeps about 400 lines.

**D5. One runtime module.** (S, low)
- 22 non-test sites build a tokio runtime:
  - 7 verbs repeat new + `block_on` + `mem::forget`;
  - 7 `drt start` blocks each build a thread plus a runtime;
  - 6 connectors each have their own `own_runtime()`.
- Change: add `runtime::block_on_leaked` and `runtime::on_thread`, which
  always leaks (fixes B9), plus one shared `drt_connector::rt` behind a
  `tokio` feature.
- Make every tokio feature imply `runtime`; 8 name `dep:tokio`
  directly today.

**D6. Extract crates along seams that already exist.** (M each)

| New crate | Contents | Needs from drt |
|---|---|---|
| `drt-netcheck` | netcheck.rs, reflect.rs, roots.rs (2.8k) | nothing |
| `drt-wg` | wireguard.rs, userspace.rs (3.3k) | a prompt callback, netcheck::gather |
| `drt-servers` (name open) | relay, bridge, stun, turn (1.4k) | a prompt callback for turn |
| `drt-root` | drt_root, deploy, consent_gate, gsr, key, modules, prompt (3.6k) | nothing (deps: drt-config, drt-caps, drt-platform, drt-connector) |
| `drt-p2p`, last | peer, http, call, signal, park, wss (~3k) | inject the REPL services through `drt_rtc::host::Service` |

- Integration tests move with their crates. `tests/wireguard.rs` is
  2,467 lines, almost all `drt::wireguard`.
- Heavy dependencies leave drt's compile unit: gotatun, smoltcp, turn
  and webrtc-util.
- The feature graph shrinks to `dep:` switches.

**D7. Retire the 0.8.0 deprecations after 0.8.0 ships.** (M, needs the owner; tied to Q-001)
- `drt tunnel` and the `tunnel` block go (in tunnel.rs, cli.rs 387-458
  and 2160-2246, and `p2p::from_tunnel*`, p2p/mod.rs:802-931). Keep
  connect/park/serve_local/stdio_to_ws/pump as `p2p/wss.rs`.
- The deprecated config spellings go: top-level `p2p`, `TunnelConfig`,
  `turn.key_file/env`, `wireguard.private_key_file/env`,
  `key_source`.
- CHANGELOG.yaml:1123 already promises "one release".

## 2. Shared plumbing (remove the copy-paste)

**P1. `drt-egress`, carved out of connectors/rest.** (L, medium; highest payoff)
- ws, ws/net and kv import rest as a library.
- ws reuses rest's parser by rewriting `ws://`→`http://` and patching
  the error text with `.replace("the rest scope","the ws scope")`
  (ws/lib.rs:343-419, net.rs:285).
- The PEM root loader exists 3 times: rest:316, ldap:706, roots.rs.
- `ClientConfig` is built 5 times. ldap uses `builder_with_provider`;
  the rest use `builder()`, which panics if aws-lc-rs ever joins.
- ssmtp takes no `extra_roots`, although the ldap doc says it does.
- rest dials only the first permitted address; ws tries each.
- Address classification exists twice: rest `is_private` and drt-rtc
  `special_purpose`.
- Change: one crate holding `Url`, a scheme-generic allowlist, the
  address policy, roots, the TLS config and `dial()`.

**P2. One HTTP/1.1 client.** (M, medium)
- There are three: reflect.rs:122-322, p2p/http.rs, and rest.
- Chunked decoding is written three times.
- p2p/signal.rs:63-95 parses HTTP by hand although httparse is linked.
- `drt://`→`http(s)://` is mapped 3 times with different edge rules:
  p2p/peer.rs:71, kv.rs:112, connectors/kv:101.
- The kv Cargo comment "one client in the binary" is false.

**P3. `drt_connector` helpers.** (S, low)
- `args`:
  - `field` has 9 copies;
  - `reply`/`map` 6;
  - `handle_arg`, `vital_arg`, `wake_arg`, `string_bytes` are identical
    in socket:799-855 and ws:1029-1095;
  - `decode<T>` covers the serde connectors, which word errors two
    ways.
- Add `From<String>` for `CallError` (about 60 `map_err` sites).
- One trait method: 8 implementors write the same 12-line `call` that
  forwards to `call_as` as Root.
- `Handles::offer`/`claim`/`until_ready`: transfer/claim is about 70
  lines each, near-identical in socket:698 and net:794. ws gets
  transfer for free.
- `drt_connector::testing` for connector tests: `call` has 18 copies,
  `field` 15.

**P4. One `Secret`.** (M; changes config surface, needs deprecation, schema, docs and changelog in one commit)
- crypto has `SecretSource` and `load_secret_value`, a re-implementation
  of `Secret` (crypto:358, :441).
- aloecrypt has `load_master`, with different conflict and length rules.
- ssmtp has `pass_env`, rest and kv `Env{env}`, and wireguard
  `preshared_key_env`.
- Only ldap uses `drt_config::Secret`, via a serde_json round-trip.
- Add `Secret::from_rmpv` and `resolve_unattended`.
- `Secret::resolve` uses `std::fs`, so a page's MemFs is ignored.

**P5. Small shared pieces.** (S each)
- msgpack: `encode` ×5 and msgpack→json ×2 (they differ on binary). Put
  them in drt-hostcall. Add `Repl::push_in` for 4 copies in repl.rs.
- One `Outbox` (Once vs Snapshot, wireguard's rule) for block reports,
  which have 6 policies today. This fixes B3.
- drt-rtc:
  - host.rs and caller.rs build the same str0m connection; share it as
    `link.rs`;
  - webrtc.rs:120 and p2p/serve.rs:80 each fill all 20 `HostConfig`
    fields; give `HostConfig` a builder.
- Attenuation logic exists twice: drt-config lib.rs:284 and
  swarm.rs:1303.
- Run limits: `(dispatcher, caps, budget, numeric)` is threaded through
  4 run functions and 2 identical cli helpers. Use a `Limits` struct and
  a `Program` enum.
- sql re-implements the fs directory scope. Move the path jail from
  connectors/fs into `drt_platform::fs`; that removes the data→fs
  connector edge.
- crypto/aloecrypt: share the label-pattern check. crypto zeroises keys
  with 5 `unsafe write_volatile`; aloecrypt uses `zeroize`.
- `relay::constant_time_eq` duplicates drt-plugin spawn.rs:329, while
  `subtle` is already in the tree.

## 3. drt-config

**C1. Move the one config reader into drt-config.** (S-M)
- `drt::config::parse` (comment stripping, located errors, validate,
  deprecations) moves to `drt_config::read`.
- It is used by `drt_root`, drt-web and dollup. This fixes B6.

**C2. Split drt-config: schema vs root format.** (M-L; dollup's import paths, softened by re-exports)
- project, consent, gsr, envelope, canon, sign, id, time, realm,
  version and modules never touch lib.rs types; only resolve.rs joins
  the two halves.
- drt-swarm needs only `Budget`/`Numeric`/`Tier`, `peer` and `NodePath`,
  yet it recompiles when `WireguardConfig` changes.
- The format half could live in the same `drt-root` crate as D6's IO
  half, or beside it.
- Fix B8 at the same time: make `consent` real or delete it.

**C3. Split files.**
- drt-config lib.rs (1,595 non-test lines) by block, into
  `services/{relay,turn,wireguard,p2p,webrtc,netcheck}.rs`.
- swarm.rs into ops, decode, sender and routing.
- engine.rs: `diluvium_engine` goes to its own file.
- drt-connector: `GrantDesk` and the capabilities menu go to a module.

## 5. Splits and hygiene

**God files to split along their own seams** (moves only):
- wireguard.rs: keys, iface, wire, drive, bridge, transport.
- netcheck.rs: verdict, gather, run/block; its 770 test lines move out.
- p2p/mod.rs: args, roles, resolve.
- crypto lib.rs: scope, jwt, totp, derive.
- rest lib.rs: url, scope, http, connector; about 900 of its lines are
  tests.
- drt-rtc host.rs: config, loop, session, tcp.
- repl.rs: the editor goes to `repl/editor.rs`.
- data: parquet and csv.
- drt-web bindings.rs: by family.

**Cargo features:**
- `cli` really means "line editor"; rename it.
- `turn-client` is test-only but sits in the shipping set.
- `full` lists features its others already imply.
- About 200 lines of history in the `[features]` comments.
- `netcheck` implies the stun *server* only because `gather` is gated
  on `stun`.
- relay and bridge imply `listen` only because the start loop does.
  After D1, both go.

**Stale comments and dead code:**
- cli.rs:17 still calls `ps` a stub.
- start.rs:32 and :599 say "no control endpoint yet".
- boot.rs's header names a function that does not exist.
- There are misattached doc comments in cli.rs (577-597, 1679).
- `tunnel::pump` always returns Ok.
- `stdlib::is_native` is used only by tests.
- net's `bus` test transport sits in production code.
- `connectors/rest` is a member only implicitly; list it.
- The reserved peer scaffolding is spread over 6 places with no live
  use; owner's call whether to keep it.

## Not worth doing

- Merge socket, net and ws: they are layered correctly; share the
  handles (P3) instead.
- Merge crypto and aloecrypt: different dependencies, and aloecrypt is
  meant to become a plugin.
- Fold stun and turn into netcheck: servers vs a client diagnostic.
- Merge relay and bridge: different protocols.
- Fold drt-ssh-web into drt-web, or drt-hostcall/drt-caps into
  drt-connector: each is a cohesive leaf.
- drt-sshd and drt-bench: clean already.

## Suggested order (each step is one or a few PRs)

1. **B1-B11 bug fixes**, each with a failing test. B11 is a mechanical
   repoint of the doc references, or deleting them; ask the owner which.
2. **Moves with no behaviour change:** D2, D4, D3 (with buildinfo), the
   god-file splits.
3. **Tables and helpers:** D1 (Block, the connector table, Outbox), D5
   (runtime), P3 (drt_connector args, call, handles, rt), P5.
4. **T1**, the test kit and one binary. It makes every later step
   cheaper to verify.
5. **Crate extractions:** drt-netcheck, then drt-wg, the servers crate,
   drt-root + C1/C2, and drt-p2p last.
6. **P1 drt-egress, then P2 one HTTP client.**
7. **After 0.8.0 ships:** D7 deprecation removal, P4 one Secret.

Steps 1-4 change no public surface. Steps 5-6 change crate layout, and
GUARANTEES.md/README.md claims need checking against them. Step 7
changes the config surface and needs the owner.
